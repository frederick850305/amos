③ 数据读写流向（Command / Query Flow）

命令侧写入经领域服务 → collectionService → db；查询侧经 lookups 派生；告警由 db 经 computed 实时计算。

flowchart LR U["UI 操作"] -->|写| DS["领域服务（业务规则校验）"] DS -->|push / removeBy| CS["collectionService"] CS -->|white-list KNOWN_KEYS| DB[("db reactive")] U -->|读列表/下拉| LK["lookups / dashboardAlerts"] LK --> DB DB -->|响应式| U DB -->|computed 派生| AL["Dashboard Alerts"]

④ 多租户 / 范围隔离（Fleet + Scope）

三艘船（Traveller / Voyager / Endeavour）为 Fleet 级分区；每船含若干部门（Engine Room / Deck / …）作为 scope。业务集合通过 installation + department 两字段做范围过滤（当前 store.scopeByDepartment 已初步实现，应在 Repository 层统一注入）。

⑤ 注册表与审计机制（Registry + Audit）

主数据（maker / vendor / criticality / location / jobDescription）统一为编码注册表供 lookup 引用；变更类操作通过 StatusLog / Archives / MaintenanceLog 留痕（建议升级为统一 EventBus + AuditLog）。

⑥ 现状 vs 目标架构（Roadmap）

当前为纯前端内存态、无持久化与契约约束；目标演进路径如上次规划：Repository 接口化 + Schema 校验 + 聚合层（CQRS-lite）+ 引用完整性 + 持久化。
